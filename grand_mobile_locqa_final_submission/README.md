# Qazaq Loc QA · комплект для проверки жюри

Содержит 145 находок и 144 подготовленных исправления. Обнаружено 10 классов
ошибок в реальных данных; все 11 поддержаны CLI и тестами. В handout нет ICU-
плюралов, поэтому находок plural_mismatch нет.

## Статус перед сдачей

**Проверка человеком ещё не подтверждена.** В ARB и report.json сохранено
`reviewed_by_human: false`. 0 переводов подтверждены носителем. Флаг true не
выставлялся вместо отсутствующей проверки. Поэтому это собранный комплект для
финальной проверки, а не заявление о выполнении критерия ручной верификации.

89 тестов pytest проходят; исходные динамические значения и защищённые токены
сохранены. Реальный flutter gen-l10n и проверка вёрстки клиента не выполнялись:
SDK и исходники игры недоступны. Структурные проверки и воспроизводимый Flutter-
проект приложены, но они не заменяют успешно выполненную компиляцию.

## Файлы

- `intl_kk_fixed.arb` — исправления и стандартная структура для Flutter.
- `glossary.csv` — 87 терминов и сленговых выражений с контекстом.
- `report.json` — ровно 145 находок по официальной схеме; описывает исходный KK.
- `report.html` — автономные фильтры по severity/типу, поиск, редактирование и
  экспорт персональной проверки. Интернет для просмотра не нужен.
- `METHODOLOGY.md` — методология, числа, ограничения, таксономия 11 классов.
- `cli/` — отдельный исходный проект Python с pyproject.toml, requirements.txt,
  tests/ и GitHub Actions. Публиковать на GitHub можно **только этот каталог**.
- `flutter_smoke/` — приватный проект для gen-l10n/analyze/test на полных данных.
- `scripts/` — проверка комплекта, подготовка Flutter и применение реального
  человеческого подтверждения.
- `audit/` — хеши, карта миграции, результаты pytest, сравнение длин и статус.
- `legacy_contract/` — неизменённые входные RU/KK и предыдущий исправленный KK,
  сохраняющий исходные идентификаторы/legacy-описания.

## Установка CLI

```bash
cd cli
python -m pip install .
python -m pip install -r requirements-dev.txt
python -m pytest -q
locqa check --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --out report.json
```

Последняя команда приведена в точности по контракту; передайте пути к своим
файлам. Для комплектных оригиналов из каталога cli:

```bash
locqa check --source ../legacy_contract/intl_ru_original.arb --target ../legacy_contract/intl_kk_original.arb --glossary ../glossary.csv --config ../audit/case_config.json --out ../audit/fresh_rule_candidates.json
```

CLI выдаёт автоматических кандидатов. Итоговые 145 находок дополнительно
отобраны/дополнены AI-анализом; сырые кандидаты и итоговый отчёт не одно и то же.

## Три миграции формата для стандартного Flutter

В исходном handout есть невалидный для метода ключ
`inventoryEquipped@description` и два ключа с заглавной первой буквой.
Для корневого исправленного файла и RU-шаблона Flutter-проекта применены:

1. `inventoryEquipped@description` перенесён в
   `@inventoryEquipped.description`. Это заметка разработчика, не строка UI.
2. `UNeedHelp` → `uNeedHelp`.
3. `TowConfirmDesc` → `towConfirmDesc`.

**Два переименования требуют обновить соответствующие обращения в клиенте.**
Не заменяйте файл в действующем приложении без учёта карты
`audit/flutter_resource_migrations.json`. Для сохранения старого контракта
приложен `legacy_contract/intl_kk_fixed_legacy_keys.arb`, но его нельзя объявлять
проверенным стандартным Flutter без адаптации шаблона/генератора.

## Проверки

Из корня распакованного комплекта:

```bash
python scripts/validate_submission.py
bash scripts/run_flutter_checks.sh
```

Второй скрипт требует установленного Flutter и выполняет pub get, gen-l10n,
analyze и test. Реальная вёрстка дополнительно проверяется в клиенте игры.

## Как получить честный human-reviewed результат

Откройте report.html, изучите каждое исправление, внесите необходимые правки,
подтвердите только действительно проверенные строки и укажите имя проверяющего.
Экспортируйте human_reviews.json. Если текст не менялся относительно предложений:

```bash
python scripts/apply_human_review.py --manifest human_reviews.json --out-dir reviewed
```

Скрипт сверяет все 144 строки, исходные тексты, хеши и перечень ошибок. Только
при наличии подтверждений он создаёт ARB и report с `reviewed_by_human: true`.
Если проверяющий изменил сам перевод, требуется новая структурная проверка
и обновление отчёта; скрипт такой случай останавливает, а не скрывает расхождение.

Все материалы с игровыми строками приватные. Не публикуйте весь архив в GitHub.
