# SÖZ · Qazaq Loc QA

Новая редакторская среда проверки казахской локализации Grand Mobile. Сайт работает в браузере через GitHub Pages. Консольная утилита использует те же `engine.js` и `advanced.js`: на одинаковых файлах и настройках результаты совпадают. Обязательных внешних библиотек и API для аудита нет.

## Самый простой запуск сайта

1. Распакуйте архив проекта.
2. Откройте свой **новый тестовый репозиторий** → **Add file → Upload files**.
3. Перетащите **все распакованные файлы** в окно загрузки, нажмите **Commit changes**. Не загружайте только ZIP; GitHub его не распакует.
4. В корне должны лежать `index.html`, `styles.css`, `app.js`, `engine.js` и остальные файлы. Они должны быть рядом, без дополнительной вложенной папки.
5. Откройте **Settings → Pages → Source: Deploy from a branch → Branch: main → / (root) → Save**. Если ваша ветка называется иначе, выберите её.
6. Дождитесь успешного запуска `pages build and deployment` во вкладке Actions. Откройте именно ссылку **Visit site** из Settings → Pages. У каждого репозитория свой адрес; корневой `имя.github.io` может открывать другой проект.
7. Сначала вы увидите **искусственный учебный набор** и готовую рабочую область. Это ожидаемое поведение. Нажмите «Загрузить ARB», чтобы проверить собственные файлы.

Для сайта не нужны Python, Node, npm, API-ключ и терминал. Файлы должны отдаваться через веб-сервер: двойной щелчок по index.html может блокировать JavaScript-модули. Используйте GitHub Pages.

## Работа локализатора

- Загрузите RU ARB и KK ARB. Глоссарий необязателен для интерфейса, но нужен для полноценного аудита и сдачи.
- Если Flutter-проект использует `use-escaping: true`, включите соответствующий флажок в дополнительных настройках. При необходимости загрузите JSON-конфигурацию правил.
- Разберите очередь по приоритету. Для каждой строки видны исходник, текущий перевод и конкретное evidence.
- Измените предложенный перевод, укажите настоящее имя и нажмите «Подтвердить строку». Флаг не выставляется автоматически. Редактирование текста снимает подтверждение.
- «Не ошибка» исключает ложную находку из финального отчёта; она остаётся в журнале решений. «Нужен контекст» оставляет находку без исправления.
- Глоссарий можно дополнить или удалить термин. После изменений пересчитайте аудит; прежние решения сбросятся после предупреждения.
- Сохраните сессию перед закрытием. «Открыть сессию» восстанавливает входные файлы и решения из вашего JSON. Автоматического хранения игровых строк в localStorage нет.
- «Экспорт результатов» выдаёт один ZIP: report.json, интерактивный автономный report.html, glossary.csv, human_reviews.json, session.json, review_log.json и summary.json.
- Для архива с fixed ARB нужно хотя бы одно подтверждение. Перед записью проверяются хеши, обязательные ключи, ICU и токены. Если структурные проблемы остались, экспорт остановится и назовёт проблемный ключ.
- Выполните **flutter gen-l10n** отдельно. Сайт не запускает Flutter и не утверждает, что компиляция прошла.

Учебные предложения подготовлены для искусственного примера. На своих данных правила дают предложения только там, где их можно вывести узко (например, цельная подпись по глоссарию). Сложные переводы редактирует человек или подготавливает отдельная опциональная команда propose.

## Консольная утилита для жюри

Нужен **Node.js 20 или новее**. Установка пакетов для запуска не требуется:

```bash
node locqa.mjs check --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --out report.json
```

Чтобы получить команду из контракта кейса:

```bash
npm link
locqa check --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --out report.json
```

Команда создаёт JSON, автономный HTML и summary. Настройки: `--config config.example.json`, `--use-escaping`, `--fail-on-high`. Коды выхода: 0 — выполнено; 1 — найден high при fail-on-high; 2 — ошибка входов/команды. Исходные файлы не перезаписываются.

Применение манифеста, экспортированного сайтом:

```bash
node locqa.mjs apply --source intl_ru.arb --target intl_kk.arb --reviews human_reviews.json --out intl_kk_fixed.arb
```

Передайте те же `--config` и `--use-escaping`, если они использовались в check. Apply не переименовывает ключи и не нормализует клиентский контракт молча.

## Необязательные предложения через LLM

Внешний вызов происходит только в консольной команде propose. API-ключ передаётся через переменную окружения `LOCQA_API_KEY`. Не вставляйте его в браузерные файлы или GitHub. Учитывайте условия передачи данных организаторов выбранному провайдеру.

```bash
node locqa.mjs propose --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --model YOUR_MODEL --limit 50 --out proposals.json
```

Поддерживается `--endpoint https://YOUR_PROVIDER/v1` с OpenAI-совместимым `/chat/completions`. Структура каждого предложения проверяется. Файл включает usage, rejected и api_cost_usd (последнее заполняется при переданных `--input-usd-per-million` и `--output-usd-per-million`). Автоматических повторов запроса нет. Провайдерский вызов на реальном API в этой поставке не проверялся.

Загрузите полученный proposals.json в поле 04 диалога загрузки вместе с исходными ARB. Предложения должны соответствовать хешам входов. Они остаются неподтверждёнными до решения человека.

```bash
npm test
```

## Важные границы

Реальные ARB Grand Mobile, старые исправления и результаты предыдущего проекта в эту новую поставку не входят. Данные нужно загрузить заново. Модель не обучалась, precision и скрытый recall не измерялись. Совпадения с неизвестными именами, контекстные синонимы и сложные кальки требуют ручного разбора. Дубликаты JSON-ключей разрешаются стандартным JSON.parse по последнему значению; повторы диагностируются в summary.duplicates. Парсер ICU проверяет структуру, а не весь поддерживаемый Flutter поднабор. Сохранённые в исходном ARB метаданные неизменённых строк сохраняются; манифест описывает подтверждения именно текущего аудита.

Не публикуйте входные игровые данные, сессии и производные отчёты в открытом GitHub. Сайт содержит только искусственный пример. Скачанный архив может включать реальные строки и предназначен для разрешённой приватной передачи.


## Версия 1.1 — новые возможности

### Готовый разбор реальных данных

Отдельный **приватный** файл `GRAND_MOBILE_OPEN_IN_SOZ.json` открывается кнопкой «Открыть сессию». В нём находятся исходные RU/KK, глоссарий и ранее подготовленные 145 находок / 144 предложения. Это загруженный предыдущий анализ, не 145 автоматически обнаруженных новой версией ошибок. Все решения начинают с pending и 0 подтверждений. Не загружайте эту сессию в GitHub. Исходный код сайта не содержит этих данных.

### Контроль шума

По умолчанию скрываются самые спорные контекстные кандидаты: разные переводы одинаковых кратких слов и термины внутри длинных фраз. Полный расширенный режим включается при загрузке или через `includeContextCandidates: true` в конфигурации. Узкие автоматические исправления переменных проходят структурную проверку и всё равно требуют человека.

### AI в интерфейсе

Кнопка «AI-проверка» позволяет указать API endpoint, модель и свой ключ. Запросы идут напрямую из браузера выбранному провайдеру только после явного согласия. Не вводите ключ на неизвестных копиях сайта. Ключ очищается после запуска/закрытия и не включается в сохранённые файлы. Сервер провайдера должен разрешать браузерные запросы (CORS); иначе используйте CLI. По умолчанию анализируются первые 100 строк; 0 означает весь набор. Это может стоить денег. При переданных тарифах сохраняется рассчитанная стоимость; без тарифов стоимость неизвестна. Остановка сохраняет завершённые пакеты, последующий запуск с той же моделью продолжает их. Для продолжения с другого компьютера сохраните сессию. Ошибка отдельного пакета не вызывает автоматический повтор. Смысл и выводы модели не считаются проверенными человеком.

```bash
node locqa.mjs ai-audit --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --model YOUR_MODEL --max-rows 100 --out ai-audit.json
node locqa.mjs ai-audit --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --model YOUR_MODEL --resume ai-audit.json --out ai-audit-continued.json
```

LOCQA_API_KEY задаётся в окружении. Дополнительные параметры: --endpoint, --batch-size (1–50), --input-usd-per-million, --output-usd-per-million. Реальный провайдерский API в этой поставке не вызывался; транспорт и ответы проверены mock-тестами.

### Дополнительный экспертный отчёт

Формат JSON: `{source_sha256, target_sha256, issues:[...официальные находки...]}`. Загружается полем 05 или `--evidence file.json` в CLI check. Тексты и хеши должны точно соответствовать исходным ARB. Импортированные reviewed_by_human сбрасываются: нужна реальная проверка. Режим `mode: "review"` показывает выбранный загруженный отчёт плюс обязательные структурные проблемы; без этого поля отчёт объединяется с правилами.

### Flutter-проект в ZIP

При экспорте fixed ARB архив дополнительно содержит flutter_check/. Запустите в этой папке `flutter pub get`, `flutter gen-l10n`, `flutter test`. Внутри только тестового проекта некорректные заглавные идентификаторы явно нормализуются; migrations.json перечисляет изменения и необходимость обновить обращения клиента. Корневой fixed ARB сохраняет оригинальные имена. Сайт не объявляет компиляцию выполненной.

### Precision без выдуманных процентов

```bash
node evaluate.mjs --report report.json --out sample.csv --size 100 --seed 42
node evaluate.mjs --report report.json --labels labels.json --out metrics.json --size 100 --seed 42
```

Человек размечает выбранные находки. labels.json — массив `{key,issue_type,valid:true|false,reviewer:"Имя"}`. Скрипт откажется от неизвестных/повторных меток. Пока не размечена вся случайная выборка, precision остаётся null. При изменении отчёта создайте выборку заново. Hidden recall остаётся неизвестным.
